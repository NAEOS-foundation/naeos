We're excited to announce the release of NAEOS v3.5.0. This release turns the engineering pipeline into an observable system and ships a reference control plane for agent-driven workflows.

## What's New

### Observability Stack

A new `naeos observability` command group provides tracing, logging, metrics, and health status from a single CLI:

```bash
naeos observability trace --name "http-request"
naeos observability log --level info --message "Pipeline finished"
naeos observability metrics
naeos observability status
```

### OTLP Trace Export

Collected spans can be exported to any OpenTelemetry-compatible collector over OTLP/HTTP:

```bash
naeos observability export --endpoint http://localhost:4318 --count 3
# Exported 3 spans to http://localhost:4318/v1/traces
```

The production daemon (`naeos serve`) is wired to the same telemetry path via its `observability.otlp_endpoint` config, and applies a per-request tracing middleware.

### Request Correlation

A correlation middleware extracts `X-Request-ID` and `X-Tenant-ID` headers and links every request to its trace, so a single audit event can be traced back to the exact request and tenant that produced it:

```go
request_id → trace_id
tenant_id  → []trace_id
```

### SLOs & Burn-Rate Alerting

A reference SLO engine computes error budgets and generates Prometheus burn-rate alert rules:

```bash
naeos observability slo --service orders-api
# Target: 99.00% | Window: 720h | Error budget: 25920 seconds
# Burn-rate alerts: page for 15m at 14.4x, ticket for 1h at 2x
```

### SIEM Export

Audit events can be streamed to a SIEM collector using Common Event Format (CEF) or NDJSON framing, with severity mapped per action and outcome:

```bash
naeos observability siem --endpoint http://localhost:9000
naeos observability siem --endpoint http://localhost:9000 --format json
```

### Investor Demo Control Plane

`naeos demo` runs a reference control plane for agent-driven workflows where security decisions — authorization, policy enforcement, capability grants, and verification — run **outside** agent control:

```bash
naeos demo --addr :9091
# NAEOS investor demo listening on http://localhost:9091
```

The control plane exposes REST endpoints for health, authorize, execute, audit, scenarios, policy, grants, verification, and reset — backed by a hardened Go HTTP server with timeouts and graceful shutdown.

### CI & Quality Hardening

- `govulncheck` scans every push/pull request for known vulnerabilities in the Go dependency graph.
- Demo builds and tests run in CI for every PR.
- The Makefile `fmt` targets now only touch git-tracked files.
