We're excited to announce the release of NAEOS v3.1.0! This release focuses on faster iteration loops and platform hardening.

## What's New

### Pipeline Caching on `naeos run`

`naeos run --cache-dir <dir>` caches intermediate stage results keyed by NEIR hash (SHA256). Rebuilds with unchanged inputs reuse cached output instead of regenerating from scratch. This cuts iterative development time significantly — especially for large specs with many modules.

```bash
naeos run --input-file spec.yaml --cache-dir .naeos-cache
```

### Run-Level Profiling

`naeos run --profile` captures per-stage timing for the 7-stage pipeline (validate → build_graph → policy_eval → schedule → generate → review → write_artifacts). `--profile-out <file>` writes the profile JSON, and `--pprof <addr>` starts a pprof HTTP server for live heap and CPU inspection.

```bash
naeos run --input-file spec.yaml --profile --profile-out profile.json
naeos run --input-file spec.yaml --pprof localhost:6060
```

### Architecture Patterns

Monolithic, microservices, and serverless patterns are now first-class in the NEIR model. The architecture pattern influences code generation, deployment manifests, and AI context bundles.

```yaml
architecture:
  pattern: microservices
  description: Event-driven microservices with gRPC inter-service communication
```

### WASM Plugin Hardening

The plugin host now requires exported metadata symbols (`PluginName`, `PluginVersion`, `PluginDescription`) and ships expanded WASM sandbox support. Plugins run in isolated memory with controlled syscalls, making the marketplace safer for third-party extensions.
