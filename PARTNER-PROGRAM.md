# NAEOS Partner Program

## Mission

NAEOS is building an ecosystem around specification-driven engineering so that teams can describe software systems once, validate the resulting engineering model, generate artifacts, and connect that model to developer and AI workflows. Partners help test these ideas in real technical contexts while NAEOS contributes open-source engineering work and documentation.

## What NAEOS Is

NAEOS is an Apache-2.0 open-source declarative engineering platform. Its documented workflow parses YAML, JSON, and HCL specifications, builds the NAEOS Engineering Intermediate Representation (NEIR), validates dependencies and policies, schedules work, and generates artifacts for Go, TypeScript, Python, Java, and Rust.

The repository also contains AI context and compiler adapters, MCP integration, profile and plugin marketplaces, a sandboxed WASM plugin path, cloud resource adapters and Terraform export, audit and evidence features, observability, security controls, and benchmark and fuzz-test tooling. These are repository capabilities; a partnership does not imply that every capability is suitable for a specific partner environment.

## Why Partner With NAEOS

Potential partner value includes:

- open-source visibility around a concrete engineering integration;
- a reference implementation and technical documentation;
- developer workflow and integration feedback;
- technical content, demos, and reference architectures where appropriate;
- participation in an open ecosystem of plugins, profiles, adapters, and research;
- engineering collaboration, testing, or architecture review;
- a public case study only when the partner approves the content.

No adoption, commercial result, audience size, or publication is guaranteed.

## Partnership Without Founder Cash

NAEOS prioritizes contribution-based partnerships. NAEOS does not assume that a partner will provide money, credits, or any other resource. Any contribution is optional, subject to eligibility and approval under the partner's own program, and mutually agreed before work starts.

### Potential contribution areas

| Area | Potential contribution |
|---|---|
| Technology | API access, developer tools, SDKs, testing infrastructure, observability, or security tools where available |
| Infrastructure | Cloud credits, compute, storage, networking, or CI/CD resources depending on partner program |
| Engineering | Code contributions, architecture review, integration work, testing, or security review |
| Research | University collaboration, researchers, students, benchmarking, or academic validation |
| Distribution | Developer communities, newsletters, technical events, meetups, or content collaboration |
| Pilot | Real users, engineering teams, workloads, or integration environments subject to authorization |

The scope, access, data handling, security review, timeline, and publicity terms must be agreed in writing. NAEOS can contribute open-source code, integration work, documentation, reference architectures, demos, technical visibility, and research collaboration; the exact contribution depends on the pilot.

## Partnership Levels

### Community Partner

Possible contributions include community sharing, contributors, events, and feedback. Potential benefits include partner recognition, community collaboration, and contributor visibility. No audience or contributor volume is promised.

### Technology Partner

Possible contributions include API access, cloud or infrastructure access, developer tooling, and integration support. Potential benefits include a reference integration, technical documentation, a public demo, and a technical case study subject to approval.

### Strategic Partner

Possible contributions include distribution, an enterprise pilot, ecosystem integration, research, or co-development. Potential benefits include joint technical initiatives, a reference architecture, ecosystem collaboration, and a joint case study subject to approval. These benefits do not imply commercial outcomes.

## How To Start

1. Review [PARTNER-REQUESTS.md](PARTNER-REQUESTS.md) and choose a narrow request.
2. Open a private or public discussion using [the partner interest form](.github/ISSUE_TEMPLATE/partner-interest.yml), depending on the information involved.
3. Agree on scope, access, ownership, security, acceptance criteria, and publicity before implementation.
4. Record the pilot using a template in [docs/partners/](docs/partners/).

For contribution and branding rules, see [docs/partners/PARTNER-POLICY.md](docs/partners/PARTNER-POLICY.md). Existing project contribution, security, conduct, and licensing rules continue to apply.
