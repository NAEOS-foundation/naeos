# Partner Fit Framework

Use this framework to qualify a proposal, not to rank companies or declare a best partner. Record evidence and unresolved questions for each assessment.

| Dimension | High fit | Medium fit | Low fit |
|---|---|---|---|
| Technical alignment | Directly maps to an existing NAEOS workflow | Requires a small extension | No clear repository-supported use case |
| Integration feasibility | Accessible API or documented interface and test environment | Some unknowns or review needed | No practical integration path |
| Developer audience overlap | Same users can benefit from a concrete example | Adjacent audience | No clear audience overlap |
| Infrastructure relevance | Enables a bounded, reproducible workflow | Useful but optional | Not relevant to the proposed pilot |
| Research relevance | Clear research question or benchmark method | Exploratory question | No measurable study scope |
| Pilot feasibility | Two-to-four-week scope with named owners | Scope needs refinement | Cannot define a small pilot |
| Mutual value | Clear value for both parties without unsupported claims | Value is plausible but untested | One-sided request |
| Accessibility | Technical contact and decision path identified | Contact path exists but is slow | No responsible contact |
| Eligibility | Partner program permits the proposed activity | Eligibility needs confirmation | Proposal conflicts with stated rules |
| Contribution feasibility | Potential contribution and limits are concrete | Contribution depends on approval | No feasible contribution identified |
