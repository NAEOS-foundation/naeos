## 1. DANA — Norman Sasono, CTO

### Public signal
DANA says 80–90% of its code is now generated with AI support. DANA also states that engineers remain responsible for architecture, validation, security, and final decisions. Its AI@Work discussion explicitly emphasizes accountability and measurable outcomes.

### Message
Hi Norman — I’ve been following DANA’s recent AI@Work discussion, especially the point that engineers remain accountable for architecture, validation, security, and the final outcome even as AI generates more of the code.

I’m building NAEOS, an open-source engineering control plane for AI coding agents.

The question we’re testing is: as coding agents move from generating code toward taking actions, how do engineering teams enforce what an agent is allowed to do — and preserve evidence of what actually happened?

We’re looking for a small number of Indonesian engineering teams to validate this around one bounded workflow. No replacement of existing coding tools; NAEOS sits around the workflow for policy, authorization, verification, and evidence.

Would you be open to a 20-minute technical exchange?

### Discovery objective
Validate whether the problem is real in DANA's engineering workflow and identify one bounded agentic workflow suitable for a pilot.

## Common follow-up after a positive response

Thanks — the goal is not a product demo first.

I’d like to understand one concrete workflow where an AI agent currently has meaningful engineering access, then map:
1. intended action,
2. allowed capabilities,
3. policy decision,
4. execution,
5. verification,
6. evidence.

If there is a real control gap, we can test NAEOS against that workflow in a bounded pilot.

## Founder operating rules

- Send individually; no bulk blast.
- Personalize the first two sentences to the recipient's documented public signal.
- Do not claim that NAEOS is already integrated with the account.
- Do not ask for a procurement or sales meeting on first touch.
- Do not infer private contact information.
- Record response, objection, next step, and technical workflow hypothesis.
- If there is no response, use one concise follow-up rather than repeated outreach.
