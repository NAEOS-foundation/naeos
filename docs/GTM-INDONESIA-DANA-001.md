## Suggested first-touch message

Hi Norman — I've been following DANA's recent AI@Work discussions, especially the emphasis on human judgment, accountability, and verifying AI output.

I'm building NAEOS, an open-source engineering control plane for AI coding agents. The problem we're testing is simple: as agents move from generating code to taking actions, how do engineering teams enforce what an agent is allowed to do and preserve evidence of what actually happened?

We're looking for a small number of Indonesian engineering teams to validate this through one bounded workflow. No replacement of existing coding tools — NAEOS sits around the workflow as policy, authorization, verification, and evidence.

Would you be open to a 20-minute technical exchange?

## Discovery questions

1. Where are AI coding agents currently used in the engineering lifecycle?
2. Which agent actions require explicit human approval?
3. What actions should be blocked automatically?
4. Where is evidence of agent actions currently recorded?
5. How are policy changes/versioning handled?
6. What would make an AI-assisted engineering workflow unacceptable from a security/risk perspective?
7. What would a useful 2–4 week technical pilot need to prove?

## Proposed pilot

One engineering team + one repository/workflow + one AI coding-agent path.

Measure:
- policy decisions
- blocked/allowed actions
- verification coverage
- evidence completeness
- developer friction
- traceability from intent to change
