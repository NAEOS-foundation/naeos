# P2.2 Evaluator Intake

## Purpose

P2.2 converts the P2.1 execution contract into a controlled external evaluation intake.

The first objective is **one independent evaluator and one reproducible run**. Do not optimize for evaluator count before the first run produces useful evidence.

## 1. Evaluator profile

Preferred evaluator:
- AI engineer
- platform / DevOps / SRE engineer
- security / governance engineer
- engineering lead working with AI coding agents

The evaluator should be able to:
- clone a public Git repository;
- run Go tooling;
- inspect generated files and JSON/Markdown evidence;
- report exact commands, environment, and observed deviations.

Prior NAEOS affiliation is not required. The evaluation is more useful when the evaluator is not involved in implementing the scenario.

## 2. Evaluation boundary

Use the fixed P2.1 boundary:
- repository: `NAEOS-foundation/naeos`
- workflow: specification-to-service generation
- control boundary: deliberately invalid policy configuration rejection
- canonical execution path: `examples/demo-cli/run-demo.sh`
- fixed commit: record before execution
- evidence: generated by the canonical run
- no production-readiness or blanket security claim

Do not add features, change acceptance criteria, or introduce a competing demo path during the run.

## 3. Intake checklist

Before sending an evaluator the run instructions, record:

| Field | Value |
|---|---|
| Evaluator | <name / handle> |
| Organization | <organization or independent> |
| Contact | <contact> |
| Intended run date | <date> |
| Fixed commit SHA | <SHA> |
| OS / architecture | <evaluator fills> |
| Go version | <evaluator fills> |
| AI-agent workflow used | baseline canonical demo |
| Control boundary | invalid policy rejection |

The evaluator should receive only the information necessary to reproduce the documented scenario. Do not request secrets or proprietary source code.

## 4. Evaluation sequence

1. Start from a clean checkout.
2. Pin the supplied commit SHA.
3. Build the CLI.
4. Execute the canonical demo.
5. Inspect the required evidence.
6. Confirm the invalid-policy rejection.
7. Record `run_id`, `specification_hash`, and `neir_hash`.
8. Run independent EvidenceBundle verification when a canonical bundle exists.
9. Record deviations without modifying the original run.
10. Select one factual determination:
   - `REPRODUCED`
   - `REPRODUCED WITH DEVIATION`
   - `NOT REPRODUCED`

## 5. Evidence submission

The evaluator should submit:
- fixed commit SHA;
- environment and `go version`;
- command exit status;
- acceptance matrix;
- `run_id`;
- `specification_hash`;
- `neir_hash`;
- policy rejection observation;
- generated artifact count;
- independent verification result or `not_applicable`;
- deviations and reproducibility;
- concise observations;
- next action.

Do not require proprietary logs, credentials, API keys, or unrelated repository data.

## 6. Deviation handling

A deviation is actionable when it is:
1. precisely described;
2. reproducible or bounded to a known environment;
3. tied to a documented step;
4. material to the evaluator workflow.

Preserve the original evidence. If a fix is made, create a new run against a new commit.

## 7. Evaluator issue record

Use the following issue title:

`P2.2 External Evaluation — Run #001 — <evaluator>`

Issue body should contain:
- evaluator identity;
- fixed commit;
- environment;
- acceptance matrix;
- evidence anchors;
- determination;
- deviations;
- observations;
- follow-up.

Do not paste secrets or sensitive source material into the issue.

## 8. P2.2 exit gate

P2.2 is complete when:
- one independent evaluator has been formally accepted;
- one fixed commit has been evaluated;
- the canonical path was attempted;
- evidence and deviations are recorded;
- the factual determination is reproducible from the submitted record;
- any engineering follow-up has a concrete acceptance criterion.

After Run #001, decide whether the observed evidence justifies a second evaluator or a product fix before scaling the cohort.

**Evidence first. Claims second.**
