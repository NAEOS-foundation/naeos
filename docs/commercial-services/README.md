## Purpose

This folder establishes a service-led, evidence-driven client delivery system for **AI Engineering Governance & Verification**. It connects positioning and qualification to assessment, scoped pilot execution, verification, reporting, acceptance, and follow-up.

This is an internal delivery framework—not a contract, certification, guarantee, or assertion that every listed capability is implemented in the NAEOS product.

## Commercial pathway

1. **Discovery & qualification** — establish use case, team, problem, constraints, stakeholders, and willingness to run a bounded evaluation.
2. **Assessment / risk audit** — map the workflow, identities, tools, policies, execution boundaries, verification, and evidence.
3. **Blueprint** — provide a prioritized target-state control architecture and implementation sequence.
4. **Scoped pilot** — evaluate one workflow in an authorized, isolated environment with explicit success/failure criteria.
5. **Implementation & expansion** — only after pilot evidence, scope approval, and capacity review.
6. **Future platform** — SaaS/platform commercialization remains gated; do not present as generally available.

## Qualification and scope minimums

Before proposal:
- named sponsor and technical owner;
- workflow and desired outcome;
- repository/environment authorization;
- available evidence and access method;
- client data classification and restrictions;
- success criteria and evaluation timeline;
- production access and action exclusions;
- budget range and procurement constraints;
- decision-maker and next-step date.

## Evidence and claims

Use the evidence classification in the register:
- **Verified** — directly inspected or reproduced and recorded.
- **Reported** — supplied by client/stakeholder, not independently verified.
- **Inferred** — analysis/hypothesis based on evidence; label assumptions.
- **Unverified** — not yet confirmed.

Scenario outcomes must be PASS, FAIL, BLOCKED, NOT TESTED, or INCONCLUSIVE. Never turn missing evidence or an untestable path into PASS.

## Delivery artifacts

For a typical assessment/pilot, provide only applicable artifacts:
- agreed scope and discovery notes;
- evidence register;
- control matrix;
- scenario test protocol and results;
- findings/risk register;
- action plan with owner and verification criteria;
- executive report/readout;
- acceptance and closure record.
