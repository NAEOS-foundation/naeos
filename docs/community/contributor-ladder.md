# NAEOS Contributor Ladder

NAEOS is an open-source engineering platform, and the community grows one
person at a time. This ladder defines the stages anyone can move through and
the concrete actions available at every stage.

We optimize for steady, useful contributions — not flashy numbers. Every rung
counts.

## The Ladder

| Stage | Label (short) | What you can do | Entry point |
|-------|----------------|-----------------|-------------|
| 1. Observer | Watch and learn | Star the repo, read the docs, follow the [Founder Journal](../../docs/community/discussions.md#categories) | `README.md`, `GETTING-STARTED.md`, [GitHub](https://github.com/NAEOS-foundation/naeos) |
| 2. User | Run NAEOS | Install the CLI, run a spec end-to-end, use `naeos doctor` | `GETTING-STARTED.md`, `examples/spec-minimal.yaml` |
| 3. Experimenter | Try and document | Build a small project from a specification; write up what worked | [Show and tell discussions](https://github.com/NAEOS-foundation/naeos/discussions/categories/show-and-tell) |
| 4. Issue reporter | Diagnose | Reproduce bugs, propose features, report documentation gaps | [Issue templates](../../.github/ISSUE_TEMPLATE/) |
| 5. Documentation contributor | Explain | Fix typos, clarify guides, add examples, update indexes | [CONTRIBUTING.md](../../CONTRIBUTING.md), `.github/ISSUE_TEMPLATE/documentation.md` |
| 6. Code contributor | Build | Fix bugs and implement features with tests | Issues labeled [`good first issue`](https://github.com/NAEOS-foundation/naeos/labels/good%20first%20issue) |
| 7. Plugin / profile contributor | Extend | Add a plugin, profile, adapter, template, or integration | [plugin_contribution.md](../../.github/ISSUE_TEMPLATE/plugin_contribution.md), `internal/pluginsdk`, `profile/` |
| 8. Maintainer | Steward | Review PRs, triage issues, own an area, mentor contributors | Reach out via Discord or Discussions |
| 9. Ecosystem partner | Amplify | Integrate NAEOS into tooling/platforms, run benchmarks, co-author research | Discussions → Ideas, or [founder contact](https://naeos.dev) |

## Why the ladder matters

- **Contributions come in all sizes.** A documentation fix and a new plugin are
  both real contributions. We celebrate each honestly.
- **Skills compound.** Issue reporting and documentation naturally grow into
  code contributions; code contributions grow into maintenance.
- **Clear paths reduce friction.** Each rung below tells you exactly where to
  start and who to talk to.

## First contribution campaigns

NAEOS runs recurring campaigns built around the ladder:

- **First star** — star the repo and follow release announcements.
- **First run** — complete `GETTING-STARTED.md` end-to-end and share the result.
- **First issue** — report one problem you actually hit (bug or docs gap).
- **First PR** — a small, well-tested change; see [`good first issue`](https://github.com/NAEOS-foundation/naeos/labels/good%20first%20issue).
- **First plugin / profile** — publish one reusable plugin or profile to the
  marketplace flow.
- **First integration** — wire NAEOS into an AI tool or platform adapter.

## Norms

- Be kind and constructive. Read [CODE_OF_CONDUCT.md](../../CODE_OF_CONDUCT.md).
- Prefer verifiable claims: reference the repository, docs, and tests before
  making product statements.
- Marketing material must never describe features that do not exist yet.
- Ask before claiming partnerships, benchmarks, or adoption figures.
