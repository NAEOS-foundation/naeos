**Hypothesis:** As AI becomes embedded in engineering workflows, the governance problem moves from model output quality to authorization of consequential actions and evidence of what happened.

**Discovery:** How are agent permissions bounded? Where are policy decisions recorded? How is an agent action revalidated before external side effects?

## Standard first-touch thesis

> As AI coding agents move from generating code to taking actions, how does your engineering organization enforce what an agent is allowed to do and preserve evidence of what actually happened?

NAEOS positioning:

> NAEOS is an open-source engineering control plane for AI coding agents. It sits around existing coding tools to provide policy, capability authorization, verification and durable evidence.

## Pilot shape

- 2–4 weeks
- 1 repository
- 1 bounded engineering workflow
- 1 AI coding-agent path
- no replacement of the existing coding tool
- explicit allow/deny capabilities
- verification before consequential actions
- evidence trail for policy decision, execution and outcome

## Discovery metrics

- unauthorized actions prevented
- policy violations detected/blocked
- verification coverage
- evidence completeness
- traceability from intent/specification to change
- developer friction
- time-to-approval
- reproducibility of the workflow

## Outreach rules

1. Use only public role/persona information.
2. Do not infer private email addresses.
3. Do not claim customer, partnership or compatibility status without evidence.
4. Lead with the engineering problem, not an NAEOS feature dump.
5. Ask for a 20-minute technical exchange before proposing a pilot.
6. Keep the first pilot bounded and reversible.
7. Treat all account hypotheses as hypotheses until validated in conversation.
