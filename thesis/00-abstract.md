# Abstract

Modern software systems increasingly span multiple programming languages, frameworks, and deployment platforms, while simultaneously being developed with the assistance of heterogeneous AI coding agents. This fragmentation produces a well-known set of pathologies: specification–implementation drift, duplicated and stale AI context files, unenforceable governance documents, and the loss of traceability between requirements and deployed artifacts. This monograph investigates whether a *declarative engineering runtime* — a platform in which a single, human-readable specification is compiled through a deterministic pipeline into code, configuration, documentation, and AI context — can structurally address these problems.

We present NAEOS (Nusantara Engineering & Architecture Operating System), an open-source engineering runtime written in Go. NAEOS introduces three principal contributions. First, **NEIR** (NAEOS Engineering Intermediate Representation), a canonical, versioned intermediate model spanning fourteen engineering domains (project, architecture, domain, modules, services, APIs, storage, infrastructure, security, AI, documentation, deployment, testing, metadata), which reduces the compiler matrix from N×M spec-to-language compilers to N generators consuming one shared IR. Second, an **executable governance model**, in which a written Engineering Constitution is compiled into machine-checkable rules enforced by validators, compilers, and AI-assisted review — turning policy from static prose into executed constraints. Third, **AI-native compilation**: the transformation of NEIR into instruction sets for six mainstream AI coding agents, plus a Model Context Protocol (MCP) server that exposes platform capabilities to any compliant agent, eliminating vendor lock-in.

The implementation comprises a staged compilation pipeline (parse → normalize → resolve → build NEIR → validate → graph → schedule → generate → review/write) with content-addressed stage caching, priority-based DAG scheduling, parallel multi-adapter generation, event-sourced observability, and a WASM-based plugin sandbox providing memory isolation and capability-based security. We evaluate the system on three axes: determinism (two independent compilations of a full example specification produced 79 byte-identical artifacts under SHA-256 comparison), performance (replicated benchmarks across small/medium/large model scales on modern hardware: 5.8 ms small-spec full runs, ~0.13 ms validation, stable allocation profiles), and quality assurance (a test suite with race-detector CI, fuzz testing, and ~77 % coverage at the time of writing).

The results indicate that specification-driven, AI-native construction is feasible without sacrificing determinism or governance: nondeterministic AI assistance can be confined to roles that do not break reproducibility, while all normative artifacts remain derived, validated, and auditable. We conclude by identifying limitations — schema evolution cost across generators, the learning curve of the specification language, and the immaturity of the plugin ecosystem — and outline future work in distributed builds, dashboard tooling, and empirical studies of drift reduction in industrial settings.

**Keywords:** declarative engineering, model-driven development, intermediate representation, deterministic pipelines, AI-native software engineering, governance as code, traceability, WebAssembly sandboxing
